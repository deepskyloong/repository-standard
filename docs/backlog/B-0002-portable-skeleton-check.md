# B-0002 — A machine-checkable checker for target repositories

## Problem

`scripts/check.ts` checks this repository: role paths, link resolution, volume and entry budgets, naming, and generated paths. It does not check placeholders, and it is not copied into a target repository. A generated repository gets the rules but not the checker, so its code gate is real and its documentation gate is not. P4 says a rule without enforcement is a slogan; the template currently exports slogans.

## Evidence

- The template's `AGENTS.md` states budgets and the change-surface rule with no command behind them.
- Four of the twelve rules in `docs/norm/rules.md` are `weak` and would remain weak even with a checker; the strong rules are only enforced inside this repository.
- A portable checker needs a small config: repository root, overlay, optional roles present, language.
- The rollout order is tracked in `B-0005`; a checker is worth extracting only after the second repository exists.
- The local checker is now TypeScript with a test per rule (`scripts/docs-model.ts`, `scripts/check-context.ts`, `scripts/doc-checks.ts`, `scripts/package-checks.ts`), so the TypeScript half of the candidate set is a copy and a trim rather than a reimplementation.

## Candidate check set

The first implementation is read-only and fails with a file path. It does not rewrite, format, or auto-fix.

1. Required files exist: `README.md`, `AGENTS.md`, `docs/README.md`, `docs/charter.md`, `docs/structure.md`, `docs/conventions.md`, `docs/committing.md`.
2. Every `docs/` directory that contains markdown has a `README.md`.
3. Every `docs/` page maps to a declared role, including the optional `docs/status.md`, `docs/knowledge/README.md`, `docs/knowledge/<kind>/README.md`, and the directory indexes; an unmapped path is a finding.
4. Every internal markdown link resolves, and every link target stays inside the repository.
5. Volume budgets hold with table delimiter rows excluded: a file above its soft line is reported as a warning, above its hard line as a failure. The numbers live in the budget table of `docs/norm/rules.md`; this set does not repeat them. Directory READMEs, work-package summaries, and package evidence follow the rows that name them.
6. Entry budgets hold: every directory `README.md` 40 rows, and every backlog and decisions index 60 rows.
7. File names match their roles: norm pages use `<slug>.md`; ADR and backlog series use four digits (`ADR-<nnnn>-slug.md`, `B-<nnnn>-slug.md`); a migrated series is zero-padded to four digits and is never renumbered.
8. No CJK in repository-maintained markdown.
9. No empty directories.
10. Files under a declared generated path start with `generated by <command> — do not edit` and a blank line.
11. The norm source is defined exactly once, on the `Norm source:` line in `AGENTS.md`; every `{{NORM_SOURCE}}` reference resolves to that source, and no absolute source path appears outside the definition.
12. A backlog index row's `Status` is one of `open`, `active`, `paused`, or `closed`; a typo is a finding.

The checker reports each finding as a code plus the facts behind it and renders `path: message`; it must not attempt a fix, and no consumer may parse the line. A fix belongs in the repository, not the gate.

## Runtime decision

Use overlay-native checkers, not a single cross-language runtime:

- TypeScript: `bun tools/check-docs.ts`, run as a stage in `bun run gate`.
- Python: `uv run python tools/check_docs.py`, run as a stage in `tools/gate.py`.

Both consume the check set above and the same fixture repository. The duplication is deliberate: a TS repository must not need Python, and a Python repository must not need Bun. Do not put the checker in `template/core/` unless a runtime-neutral implementation appears.

## Revisit when

The first repository is forged, or the first migration reaches its overlay step. The check set above is ready before that trigger; implementation waits for the first real target repository. A JSON surface, and with it `docs/contracts/findings.md`, waits for the first consumer that reads records rather than lines.
