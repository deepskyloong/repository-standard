# W05 — Return coded findings from this repository's checker

**Depends on**: W03

The live instance. `Finding` is `{ level, message }`, and every check builds the sentence at the point it fires — `fail(\`missing required file: ${name}\`)`. Nothing carries a code or the facts, so a consumer cannot group, suppress, or test a message without parsing English. The refactor gives the record a code and params, moves the wording into one catalog, and makes `scripts/check.ts` the only renderer.

**Done when**:

- No check function composes a sentence; it names a code and passes params.
- `Finding` carries `code`, `level`, and `params`; the catalog validates at import: unique codes, known levels, every template formats with dummy params.
- Every code has a fixture, and the coverage assertion `set(CATALOG) - seen == empty` passes.
- `bun run gate` is green and the test count is recorded.

**Evidence**: commit `<hash>`; the coverage test output; the before and after count of string-building sites.
